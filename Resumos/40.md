## 📌 Solução de Problemas de Roteamento

### 🎯 Objetivo
Identificar exatamente em qual salto (*hop*) o pacote de dados é descartado ou sofre latência excessiva ao tentar alcançar o destino.

### 🛠️ Ferramentas & Comandos Vitais

| Comando | Parâmetros / Exemplo | Finalidade no Troubleshooting |
| :--- | :--- | :--- |
| `ping` | `ping -c 4 8.8.8.8` | Teste básico de alcance ICMP e medição de latência/perda de pacotes. |
| `tracert` (Win) / `traceroute` (Linux) | `tracert 8.8.8.8` | Mapeia todos os roteadores intermediários até o destino. |
| `route print` (Win) / `ip route` (Linux) | `ip route show` | Exibe a tabela de roteamento do próprio sistema operacional. |
| `mtr` | `mtr 8.8.8.8` | Combina `ping` e `traceroute` para análise contínua do caminho da rede. |

### 🧪 Laboratório Prático & Troubleshooting

#### **1. Rastreando o Caminho até o Destino e Checando Tabela Local**
```bash
# Rastreando saltos de rede
tracert 8.8.8.8

# Exibindo tabela de roteamento local
ip route
```
![Trace e Tabela de Roteamento](assets/aula40-roteamento.png)

* **Análise dos Resultados:**
  * **Gateways:** Mostra o primeiro salto (roteador local/Virtual Router da VPC).
  * **Asteriscos (*):** Podem indicar bloqueio de ICMP por firewalls no caminho ou perda real de conexão.

### ☁️ Visão Cloud & Cyber Security
* **Tabelas de Roteamento VPC:** Verifique se a sub-rede possui rota default (`0.0.0.0/0`) apontada para o **Internet Gateway (IGW)** (se pública) ou para o **NAT Gateway** (se privada).
* **VPC Peering / Transit Gateway:** Confirme se os dois lados do emparelhamento possuem rotas explícitas indicando o bloco CIDR do outro ambiente.
