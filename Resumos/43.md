## 📌 Solução de Problemas de HTTP/TLS

### 🎯 Objetivo
Investigar falhas na Camada de Aplicação (códigos de status HTTP) e erros na negociação de certificados de criptografia (SSL/TLS).

### 🛠️ Ferramentas & Comandos Vitais

| Comando | Parâmetros / Exemplo | Finalidade no Troubleshooting |
| :--- | :--- | :--- |
| `curl` | `curl -Iv https://google.com` | Exibe o *Handshake* TLS, cabeçalhos de resposta e códigos HTTP. |
| `openssl` | `openssl s_client -connect domain:443` | Inspeciona a cadeia completa de certificados digitais do servidor. |

### 🧪 Laboratório Prático & Troubleshooting

#### **1. Inspecionando o Handshake TLS e Cabeçalhos HTTP**
```bash
# Detalhando a conexão HTTP/TLS
curl -v -I https://google.com
```
![Análise HTTP e TLS com cURL](assets/aula43-httptls.png)

* **Análise dos Resultados:**
  * **Server Certificate:** Confirma o emissor, a validade e o nome do domínio (SAN) do certificado SSL.
  * **HTTP Status Code:** `200 OK` (Sucesso), `403 Forbidden` (Acesso negado por permissão/WAF), `502/504` (Falha de comunicação no backend/Gateway).

### ☁️ Visão Cloud & Cyber Security
* **Erros Comuns na Nuvem:**
  * **502 Bad Gateway / 504 Gateway Timeout:** O Load Balancer conseguiu receber a requisição, mas a instância/container atrás dele não respondeu a tempo.
  * **SSL/TLS Termination:** Erros de handshake quando a terminação de certificado ocorre no CloudFront ou ALB e há incompatibilidade de *ciphers*.

## 💡 Checklist Geral de Troubleshooting de Redes

- [ ] **Camada de Nome (DNS):** O nome resolve para o IP correto? (`nslookup` / `dig`)
- [ ] **Camada de Rede (IP/Roteamento):** O destino é alcançável? Há rota configurada? (`ping` / `tracert`)
- [ ] **Camada de Transporte (Firewall/TCP):** A porta necessária está aberta e liberada? (`nc` / `Security Groups`)
- [ ] **Camada de Aplicação (HTTP/TLS):** Os certificados estão válidos e a aplicação está respondendo com HTTP 200? (`curl` / `openssl`)
