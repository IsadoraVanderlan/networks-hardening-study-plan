# Resumo de Estudos: HTTP e HTTPS

---

## 1. O que são HTTP e HTTPS?

O **HTTP** e o **HTTPS** são protocolos da **Camada de Aplicação (L7)** que formam a base da comunicação de dados na Web, permitindo a transferência de recursos (HTML, JSON, mídia, etc.) entre clientes (navegadores/APIs) e servidores.

- **HTTP (Porta 80 TCP):** Comunicação em texto puro (_plaintext_). Os dados trafegam sem criptografia, estando vulneráveis à interceptação e manipulação.
- **HTTPS (Porta 443 TCP):** Adiciona uma camada de segurança sobre o HTTP encapsulando o tráfego via **TLS/SSL** (_Transport Layer Security_). Garante confidencialidade, integridade e autenticidade.

---

## 2. O Handshake TLS/SSL (Como o HTTPS Funciona)

Para estabelecer uma conexão segura HTTPS, o cliente e o servidor realizam o **TLS Handshake** antes da troca de dados HTTP:

```text
[Cliente / Navegador]                                 [Servidor Web]
        |                                                   |
        | -------- 1. Client Hello (Versão, Ciphers) -----> |
        |                                                   |
        | <------- 2. Server Hello + Certificado Digital -- |
        |                                                   |
        | (Valida certificado com a Autoridade Certificadora)|
        |                                                   |
        | -------- 3. Troca de Chaves (Pre-Master Secret) -> |
        |                                                   |
        | <======= 4. Conexão Criptografada (Chave Simétrica) =>
```

1. **Client Hello:** O cliente envia versões do TLS suportadas e algoritmos de criptografia (_Cipher Suites_).
2. **Server Hello & Certificado:** O servidor escolhe o algoritmo, envia seu **Certificado Digital X.509** contendo a **Chave Pública**.
3. **Validação e Troca de Chaves:** O cliente valida o certificado junto a uma CA (_Certificate Authority_) confiável e utiliza a chave pública do servidor para negociar uma **chave simétrica temporária** (criptografia assimétrica).
4. **Sessão Criptografada:** Toda a comunicação subsequente utiliza a **chave simétrica** (muito mais rápida) para criptografar os dados HTTP.

## 3. Principais Métodos HTTP (_Verbos_)

| Método     | Função Principal                                                                              | Idempotente? |
| :--------- | :-------------------------------------------------------------------------------------------- | :----------- |
| **GET**    | Solicita a recuperação de um recurso do servidor. Não deve alterar o estado do sistema.       | **Sim**      |
| **POST**   | Envia dados para o servidor criar um novo recurso ou processar informações (ex: formulários). | **Não**      |
| **PUT**    | Substitui integralmente um recurso existente ou o cria caso não exista.                       | **Sim**      |
| **PATCH**  | Aplica modificações parciais em um recurso existente.                                         | **Não**      |
| **DELETE** | Remove o recurso especificado no servidor.                                                    | **Sim**      |
| **HEAD**   | Retorna apenas os cabeçalhos (_headers_) da requisição, sem o corpo da resposta (_body_).     | **Sim**      |

## 4. Códigos de Status HTTP (_Status Codes_)

Os códigos de resposta de 3 dígitos dividem-se em 5 famílias:

| Faixa   | Categoria          | Descrição                                                                      | Exemplos Conhecidos                                                       |
| :------ | :----------------- | :----------------------------------------------------------------------------- | :------------------------------------------------------------------------ |
| **1xx** | _Informativo_      | Requisição recebida e em processamento.                                        | `100 Continue`                                                            |
| **2xx** | _Sucesso_          | Ação recebida, compreendida e aceita com sucesso.                              | `200 OK`, `201 Created`, `204 No Content`                                 |
| **3xx** | _Redirecionamento_ | O cliente precisa realizar ações adicionais para concluir a requisição.        | `301 Moved Permanently`, `302 Found`                                      |
| **4xx** | _Erro do Cliente_  | A requisição contém sintaxe incorreta ou não pode ser processada pelo cliente. | `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`   |
| **5xx** | _Erro do Servidor_ | O servidor falhou ao processar uma requisição válida.                          | `500 Internal Server Error`, `502 Bad Gateway`, `503 Service Unavailable` |

## 5. Relevância em Cloud Security e Boas Práticas

Em arquiteturas de nuvem modernas (AWS CloudFront, ALB, ACM, WAF), a proteção e otimização do tráfego web é prioridade máxima.

### 5.1 Vetores de Ataque e Vulnerabilidades

- **Man-in-the-Middle (MitM):** Interceptação de dados sensíveis (senhas, cookies) em conexões HTTP desprotegidas.
- **Ataques de Camada 7 (L7):** Injeções (SQLi, XSS), manipulação de cabeçalhos e requisições HTTP maliciosas.
- **Session Hijacking:** Roubo de cookies de sessão trafegados em HTTP não criptografado.

### 5.2 Controles de Segurança e Práticas em Nuvem

- **SSL/TLS Termination no Load Balancer:** O Application Load Balancer (ALB) decodifica o tráfego HTTPS usando certificados do **AWS Certificate Manager (ACM)**, reduzindo a carga de processamento dos servidores/instâncias backend.
- **Redirecionamento HTTP para HTTPS (HTTPtoHTTPS Redirect):** Forçar todo o tráfego da porta 80 a ser redirecionado para a porta 443 via código de status `301`.
- **Cabeçalhos de Segurança HTTP (_Security Headers_):**
  - **HSTS (_HTTP Strict Transport Security_):** Força os navegadores a se comunicarem **apenas via HTTPS** por um período especificado.
  - **CSP (_Content Security Policy_):** Previne ataques de XSS restringindo quais origens podem carregar scripts.
- **Web Application Firewall (WAF):** Inspeciona o payload HTTP/HTTPS na Camada 7 para mitigar ameaças da lista OWASP Top 10 e barrar bots.
