# Resumo de Estudos: Portas TCP/UDP e Portas Efêmeras

---

## 1. O que são Portas na Camada de Transporte (L4)?

As **portas lógicas** são numerações de 16 bits (variando de **0 a 65535**) que identificam aplicações ou serviços específicos dentro de uma máquina na rede.

- **Endereço IP:** Identifica a máquina de destino na rede (o "prédio").
- **Porta Lógica:** Identifica a aplicação/serviço que processará os dados dentro daquela máquina (a "sala").

Uma comunicação completa na internet é identificada por um conjunto de 5 elementos chamado **Socket/5-Tuple**:

1. IP de Origem
2. IP de Destino
3. Porta de Origem (_Porta Efêmera_)
4. Porta de Destino (_Porta do Serviço_)
5. Protocolo (TCP ou UDP)

---

## 2. As Faixas de Portas

As 65.536 portas disponíveis são categorizadas internacionalmente pela IANA (_Internet Assigned Numbers Authority_) em 3 faixas:

| Faixa de Portas   | Categoria                                   | Descrição e Aplicação                                                         | Exemplos                                                              |
| :---------------- | :------------------------------------------ | :---------------------------------------------------------------------------- | :-------------------------------------------------------------------- |
| **0 a 1023**      | **Portas Conhecidas** (_Well-Known_)        | Reservadas para serviços do sistema operacional e protocolos padrão.          | **22** (SSH), **53** (DNS), **80** (HTTP), **443** (HTTPS)            |
| **1024 a 49151**  | **Portas Registradas** (_Registered_)       | Atribuídas pela IANA a aplicações específicas de terceiros e bancos de dados. | **3306** (MySQL), **5432** (PostgreSQL), **3389** (RDP)               |
| **49152 a 65535** | **Portas Efêmeras** (_Dynamic / Ephemeral_) | Alocadas temporariamente pelo sistema cliente para iniciar conexões de saída. | Portas aleatórias geradas por navegadores e clientes no acesso à web. |

_Nota: Alguns sistemas operacionais utilizam faixas customizadas para portas efêmeras (ex: Linux Kernel utiliza a faixa de **32768 a 60999**)._

---

## 3. Mecânica das Portas Efêmeras (_Ephemeral Ports_)

Quando um cliente (navegador) acessa um servidor web na porta 443 (HTTPS), o sistema operacional do cliente sorteia uma porta efêmera livre para receber a resposta de volta.

```text
Cliente (Seu Computador)                             Servidor Web (Google)
IP: 192.168.1.10                                     IP: 142.250.190.46
  |                                                        |
  | -------- Requisição (Origem: 51234 -> Destino: 443) --> |
  |                                                        |
  | <------- Resposta   (Origem: 443 -> Destino: 51234) --- |
  |                                                        |
```

- **Ciclo de Vida:** A porta efêmera é alocada no momento em que a requisição é iniciada e é liberada e devolvida ao pool do sistema operacional assim que a conexão é encerrada.

---

## 4. Impacto em Cloud Security (Security Groups vs. NACLs)

O entendimento de portas efêmeras é essencial para a criação de políticas de controle de tráfego em nuvem (como AWS VPC, Azure VNet e GCP VPC).

### 4.1 Security Groups (Stateful)

- **Comportamento:** Guardam o estado da conexão (_Stateful_).
- **Impacto:** Se você cria uma regra de entrada (_Inbound_) permitindo o tráfego TCP na porta **443**, o Security Group permite automaticamente que o tráfego de resposta saia pela **porta efêmera** do cliente, sem necessidade de regra explícita de saída.

### 4.2 Network ACLs / NACLs (Stateless)

- **Comportamento:** Não guardam o estado da conexão (_Stateless_).
- **Impacto:** Avaliam o tráfego de entrada e de saída de forma totalmente independente.
- **Regra Prática:** Se você permite a entrada da porta **443** em uma NACL, **deve obrigatoriamente** criar uma regra de saída (_Outbound_) liberando a faixa de **portas efêmeras (1024–65535)** para que os pacotes de resposta consigam sair da sub-rede e retornar ao cliente.

### 4.3 Riscos de Segurança e Vetores de Ataque

- **Port Exhaustion (Esgotamento de Portas):** Se uma aplicação abre milhares de conexões de saída sem fechá-las adequadamente (ex: vazamento de conexões HTTP ou bancos de dados), o sistema operacional fica sem portas efêmeras disponíveis, impedindo novas comunicações de rede.
- **Exposição de Portas Conhecidas:** Manter portas conhecidas abertas para o bloco `0.0.0.0/0` (como a porta 22/SSH ou 3389/RDP) atrai _scans_ automatizados e ataques de força bruta.
