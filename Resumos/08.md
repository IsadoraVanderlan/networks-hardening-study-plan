# 🌐 Resumo de Aula: Subnetting e Cálculo de Sub-redes

**Subnetting** (Divisão de Sub-redes) é a técnica de pegar uma rede grande e dividi-la em redes menores e independentes. É como pegar um andar inteiro de um prédio e criar várias salas de reunião fechadas: melhora a segurança, reduz o tráfego desnecessário e organiza a infraestrutura! 🏢⚡

---

## 🎯 1. Por que fazer Subnetting?

- **Redução do Domínio de Broadcast**: Evita que o tráfego de broadcast de um setor (ex: Marketing) atinja e pague a rede de outro (ex: TI).
- **Segurança**: Permite aplicar regras de firewall e controle de acesso entre departamentos diferentes.
- **Economia de Endereços IP**: Evita o desperdício de blocos inteiros de IP para poucos dispositivos.
- **Organização**: Facilita o gerenciamento e a identificação de problemas na rede.

---

## 🧮 2. Entendendo os Bits da Máscara (Notação CIDR)

A máscara de sub-rede define onde termina a rede e onde começam os hosts. No cálculo de sub-redes, nós **"tomamos emprestados" bits da parte de Host para a parte de Rede**.

### A Regra das Potências de 2

Em redes, trabalhamos com a base binária:

- **Para achar o número de Sub-redes criadas**: $2^n$ (onde $n$ é o número de bits de host tomados emprestados).
- **Para achar o número de Hosts por sub-rede**: $2^h - 2$ (onde $h$ é o número de bits de host restantes).
  - ⚠️ _Subtraímos $2$ porque o **primeiro IP** é o Endereço de Rede e o **último IP** é o Endereço de Broadcast!_

## 🔢 3. Tabela de Apoio para Máscaras Frequentes (/24 a /30)

| CIDR    | Máscara de Sub-rede | Bits de Host ($h$) | Total de IPs ($2^h$) | IPs Úteis para Hosts ($2^h - 2$)         |
| :------ | :------------------ | :----------------- | :------------------- | :--------------------------------------- |
| **/24** | `255.255.255.0`     | 8 bits             | 256                  | **254**                                  |
| **/25** | `255.255.255.128`   | 7 bits             | 128                  | **126**                                  |
| **/26** | `255.255.255.192`   | 6 bits             | 64                   | **62**                                   |
| **/27** | `255.255.255.224`   | 5 bits             | 32                   | **30**                                   |
| **/28** | `255.255.255.240`   | 4 bits             | 16                   | **14**                                   |
| **/29** | `255.255.255.248`   | 3 bits             | 8                    | **6**                                    |
| **/30** | `255.255.255.252`   | 2 bits             | 4                    | **2** _(Ideal para links ponto a ponto)_ |

## 🛠️ 4. Exemplo Prático Passo a Passo

**Desafio**: Dividir a rede `192.168.1.0/24` para atender a **4 departamentos**, cada um precisando de até 50 hosts.

### Passo 1: Descobrir quantos bits pegar emprestado

- Precisamos de 4 sub-redes.
- Pela fórmula $2^n \ge 4 \implies n = 2$ bits.
- Nova máscara: $/24 + 2 = \mathbf{/26}$ (`255.255.255.192`).

### Passo 2: Descobrir o tamanho do bloco (Tamanho do Salto)

- Restaram $8 - 2 = 6$ bits de host ($h = 6$).
- Total de IPs por bloco: $2^6 = 64$ IPs.
- Salto = **64** (O tamanho de cada sub-rede).

### Passo 3: Mapear as sub-redes geradas

| Sub-rede       | Endereço de Rede | Primeiro IP Útil | Último IP Útil  | Broadcast       |
| :------------- | :--------------- | :--------------- | :-------------- | :-------------- |
| **Sub-rede 1** | `192.168.1.0`    | `192.168.1.1`    | `192.168.1.62`  | `192.168.1.63`  |
| **Sub-rede 2** | `192.168.1.64`   | `192.168.1.65`   | `192.168.1.126` | `192.168.1.127` |
| **Sub-rede 3** | `192.168.1.128`  | `192.168.1.129`  | `192.168.1.190` | `192.168.1.191` |
| **Sub-rede 4** | `192.168.1.192`  | `192.168.1.193`  | `192.168.1.254` | `192.168.1.255` |

---

## 💡 Dica de Ouro (Macetes Rápidos)

- **O Tamanho do Salto Magnético**: Para achar o intervalo entre os blocos sem fazer contas binárias longas, subtraia o último octeto da máscara de 256.
  - Exemplo para máscara `255.255.255.192`: $256 - 192 = \mathbf{64}$. As sub-redes vão saltar de 64 em 64!
- **Link Ponto a Ponto (Roteador a Roteador)**: Sempre use **/30**. Ele entrega apenas 2 IPs válidos, evitando desperdício de endereços.
