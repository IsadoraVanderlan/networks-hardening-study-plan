# Resumo de Estudos: Handshake TCP de 3 Vias (Three-Way Handshake)

---

## 1. Conceito e Objetivo

O **Three-Way Handshake** (Aperto de Mão de Três Vias) é o procedimento padrão executado na **Camada de Transporte (Camada 4)** para **estabelecer uma conexão lógica e confiável** entre duas máquinas (Cliente e Servidor) antes do envio de qualquer dado de aplicação (HTTP, SSH, etc.).

### Objetivos Principais:

- **Sincronizar** os números de sequência iniciais (_Initial Sequence Numbers - ISN_) de ambos os lados.
- **Negociar** parâmetros de controle de fluxo e tamanho de pacote (ex: _Maximum Segment Size - MSS_).
- **Garantir** que ambos os nós estejam prontos e acessíveis para se comunicar.

## 2. O Fluxo de 3 Etapas (SYN $

ightarrow$ SYN-ACK $
ightarrow$ ACK)

```text
Cliente (Origem)                               Servidor (Destino)
   [CLOSED]                                         [LISTEN]
      |                                                |
      | -------------- 1. SYN (SEQ = X) -------------> |  (Estado: SYN-RCVD)
      |                                                |
      | <------- 2. SYN-ACK (SEQ = Y, ACK = X+1) ----- |
      |                                                |
   [ESTABLISHED]                                       |
      | -------------- 3. ACK (ACK = Y+1) -----------> |  (Estado: ESTABLISHED)
      |                                                |
```

### 1. Passo 1: SYN (_Synchronize_)

- **Direção:** Cliente $
ightarrow$ Servidor.
- **Flag ativa:** `SYN` = 1.
- **O que acontece:** O cliente envia um pacote inicial solicitando a abertura da sessão e informando seu número de sequência inicial ($SEQ = X$).
- **Estado do Cliente:** Transita de `CLOSED` para `SYN-SENT`.

### 2. Passo 2: SYN-ACK (_Synchronize-Acknowledge_)

- **Direção:** Servidor $
ightarrow$ Cliente.
- **Flags ativas:** `SYN` = 1, `ACK` = 1.
- **O que acontece:** O servidor confirma que recebeu o pedido do cliente ($ACK = X + 1$) e envia seu próprio número de sequência inicial ($SEQ = Y$).
- **Estado do Servidor:** Transita de `LISTEN` para `SYN-RECEIVED` (_Half-Open Connection_).

### 3. Passo 3: ACK (_Acknowledge_)

- **Direção:** Cliente $
ightarrow$ Servidor.
- **Flag ativa:** `ACK` = 1.
- **O que acontece:** O cliente confirma o recebimento do número de sequência do servidor ($ACK = Y + 1$).
- **Estado Final:** Ambos os nós atingem o estado `ESTABLISHED`. A partir deste momento, os dados da aplicação (HTTP GET, conexões TLS, etc.) começam a ser transmitidos.

---

## 3. TCP Flags Utilizadas

| Flag    | Nome Completo | Função no Handshake                                                                                             |
| :------ | :------------ | :-------------------------------------------------------------------------------------------------------------- |
| **SYN** | _Synchronize_ | Utilizada nos passos 1 e 2 para sincronizar números de sequência no início da sessão.                           |
| **ACK** | _Acknowledge_ | Utilizada nos passos 2 e 3 (e em quase todas as trocas subsequentes) para confirmar o recebimento de pacotes.   |
| **FIN** | _Finish_      | Utilizada posteriormente para o encerramento cortês da conexão (_Four-Way Handshake_).                          |
| **RST** | _Reset_       | Utilizada para abortar a conexão imediatamente caso ocorra um erro, rejeição de porta ou bloqueio por firewall. |

## 4. Relevância em Cloud Security e Ameaças

O entendimento do Handshake TCP é fundamental para identificar comportamentos anômalos na rede e configurar controles de segurança em ambientes de nuvem.

### 4.1 Ataque SYN Flood (Negação de Serviço - DoS/DDoS)

- **Como funciona:** O atacante dispara milhares de pacotes `SYN` com endereços IP de origem falsificados (_IP Spoofing_). O servidor responde com `SYN-ACK` e reserva espaço em memória aguardando o `ACK` final, que nunca é enviado.
- **Impacto:** Esgota a tabela de conexões (_Backlog Queue_) do servidor, impedindo que usuários legítimos se conectem.
- **Mitigação em Nuvem:**
  - **SYN Cookies:** O servidor não aloca memória até receber o `ACK` válido com o cookie numérico retornado.
  - **Proteção na Borda (AWS Shield / Cloudflare):** Inspeção e descarte do tráfego malicioso antes de atingir as instâncias EC2/containers.
  - **Rate Limiting / WAF:** Limitação de requisições por IP de origem.

### 4.2 Táticas de Reconhecimento (Port Scanning com Nmap)

Analistas e invasores utilizam o comportamento das flags TCP para realizar mapeamento de infraestrutura:

- **TCP SYN Scan (`nmap -sS`):** O scanner envia `SYN`. Se receber `SYN-ACK`, descobre que a **porta está aberta** e envia um `RST` para interromper o Handshake antes de completar a conexão (evitando logs na aplicação). Se receber `RST`, a **porta está fechada**.
