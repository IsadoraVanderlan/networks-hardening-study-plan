# Resumo de Estudos: DHCP — Protocolo de Configuração Dinâmica de Hosts

---

## 1. O que é o DHCP?

O **DHCP** é um protocolo de rede que automatiza a atribuição de endereços IP e parâmetros de rede para dispositivos (_hosts_) em uma rede Local (LAN) ou Virtual (VPC). Ele elimina a necessidade de configuração manual de IP, prevenindo conflitos de endereçamento e reduzindo custos operacionais.

- **Camada no Modelo OSI:** Camada de Aplicação (L7).
- **Camada de Transporte:** UDP.
- **Portas Utilizadas:**
  - **Porta 67 UDP:** Servidor DHCP (escuta requisições dos clientes).
  - **Porta 68 UDP:** Cliente DHCP (recebe as respostas do servidor).

---

## 2. O Processo de Conexão DORA (4 Passos)

Quando um dispositivo conecta à rede, ele executa o fluxo **DORA** para obter suas configurações:

```text
[Cliente DHCP]                                    [Servidor DHCP]
      |                                                  |
      | ------ 1. DISCOVER (Broadcast: 255.255.255.255) -> |
      |                                                  |
      | <----- 2. OFFER    (Unicast / Broadcast) -------- |
      |                                                  |
      | ------ 3. REQUEST  (Broadcast) -----------------> |
      |                                                  |
      | <----- 4. ACKNOWLOGEMENT (ACK) ------------------ |
      |                                                  |
```

1. **Discover (Descoberta):** O cliente envia uma mensagem em _Broadcast_ (`255.255.255.255`) procurando qualquer servidor DHCP disponível na rede.
2. **Offer (Oferta):** O servidor responde oferecendo um endereço IP disponível, máscara de sub-rede, gateway e tempo de concessão (_Lease Time_).
3. **Request (Solicitação):** O cliente responde formalizando o pedido do IP oferecido (em _Broadcast_, avisando a outros possíveis servidores que aceitou essa proposta).
4. **Acknowledgment (ACK - Confirmação):** O servidor confirma a alocação, envia o conjunto de opções de rede e o temporizador do _Lease_ é iniciado.

---

## 3. Principais Opções do DHCP (_DHCP Options_)

O protocolo DHCP permite entregar parâmetros adicionais além do IP através do campo de opções:

| Opção         | Nome               | Descrição e Aplicação                                                         |
| :------------ | :----------------- | :---------------------------------------------------------------------------- |
| **Option 1**  | _Subnet Mask_      | Define a máscara de sub-rede (ex: `255.255.255.0`).                           |
| **Option 3**  | _Router / Gateway_ | IP do roteador/gateway padrão para saída de tráfego.                          |
| **Option 6**  | _DNS Servers_      | IPs dos servidores DNS que o cliente deve utilizar para resolução de nomes.   |
| **Option 15** | _Domain Name_      | Nome do domínio padrão de busca da rede (ex: `corp.local` ou `ec2.internal`). |
| **Option 42** | _NTP Servers_      | IPs dos servidores de sincronização de tempo (_Network Time Protocol_).       |

---

## 4. Tipos de Alocação de IP

- **Dinâmica:** O IP é alocado temporariamente por um período determinado pelo _Lease Time_. O cliente renova automaticamente o _lease_ quando atinge 50% do tempo.
- **Reserva Estática (DHCP Reservation):** Mapeia o endereço físico (**MAC Address**) do dispositivo para um IP fixo, garantindo que o dispositivo sempre receba o mesmo IP via DHCP.
- **Manually Assigned:** Atribuição feita manualmente no próprio sistema operacional (sem uso de DHCP).

## 5. Relevância em Cloud Security e Vetores de Ataque

Em redes corporativas e infraestruturas de nuvem (AWS DHCP Option Sets, Azure Virtual Networks), o controle do DHCP é essencial para manter a integridade da rede.

### 5.1 Vetores de Ataque Comuns

- **Rogue DHCP Server (Servidor DHCP Falso):** Um atacante instala um servidor DHCP não autorizado na rede para fornecer gateways e servidores DNS maliciosos aos clientes, realizando ataques de _Man-in-the-Middle (MitM)_.
- **DHCP Starvation Attack (Esgotamento de Leases):** O atacante gera milhares de requisições `DHCP DISCOVER` usando endereços MAC forjados (_Spoofing_), consumindo todo o pool de IPs do servidor e causando Negação de Serviço (DoS) para novos clientes.

### 5.2 Mecanismos de Proteção e Práticas em Nuvem

- **DHCP Snooping:** Funcionalidade de segurança em switches L2 que inspeciona o tráfego DHCP e bloqueia respostas oriundas de portas não autorizadas (_untrusted ports_).
- **DHCP Relay Agent:** Permite retransmitir requisições `DISCOVER` (Broadcast) através de roteadores para um servidor DHCP centralizado na rede.
- **DHCP Option Sets em Nuvem (AWS/Azure):** Na nuvem, o serviço de DHCP é gerenciado nativamente pelo _hypervisor_ (controlado via software). Os administradores configuram _DHCP Option Sets_ para definir domínios e DNS corporativos de forma automatizada em instâncias EC2 e VMs.

## 6. Resumo Executivo para Entrevistas

> **"O DHCP opera na Camada de Aplicação sobre UDP (portas 67 e 68) para automatizar a atribuição de endereços IP e opções de rede via processo DORA (Discover, Offer, Request, ACK). Em segurança de redes, é vulnerável a ataques de Rogue DHCP e DHCP Starvation, mitigados por DHCP Snooping em switches físicos. Na nuvem, o DHCP é virtualizado via software e gerenciado através de DHCP Option Sets para padronizar configurações de VPCs."**
