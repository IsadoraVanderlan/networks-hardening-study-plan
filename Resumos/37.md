# nc / Netcat – Teste de Conectividade e Portas

## 💡 Analogia do Dia a Dia

O Netcat (nc) é o Canivete Suíço das Redes. Ele funciona como um cabo de extensão virtual direto: você escolhe um IP e uma porta, e o Netcat abre um tubo transparente de comunicação entre os dois lados. Se você quer saber se uma "porta de entrada" de um prédio/servidor está aberta ou fechada sem precisar rodar uma aplicação complexa, o Netcat faz isso em segundos.

## 🛠️ Para que serve?

Testar conectividade TCP/UDP em portas específicas, transferir arquivos brutos, criar servidores/listeners temporários para testes e diagnosticar bloqueios de firewall.

## 📌 Principais Parâmetros

-z: Modo Zero-I/O (apenas verifica se a porta está aberta, sem enviar dados).

-v: Modo verbal (verbose), exibe detalhes da conexão.

-w <segundos>: Define o tempo limite (timeout) para a tentativa de conexão.

-u: Utiliza protocolo UDP em vez do padrão TCP.

-l: Coloca o Netcat no modo de escuta (listen), agindo como um servidor temporário na porta especificada.

-p: Especifica a porta local a ser usada.

## 💻 Exemplos Práticos

# Testar se a porta 80 (HTTP) ou 443 (HTTPS) de um servidor está aberta
nc -zv exemplo.com 80
nc -zv exemplo.com 443

# Testar se a porta 53 (DNS via UDP) está acessível
nc -zvu 8.8.8.8 53

# Criar um servidor simples de escuta na porta 4444 (em uma máquina)
nc -l -p 4444

# Conectar-se ao servidor criado acima (de outra máquina)
nc 192.168.1.50 4444


💡 Dica Criativa: O ping usa ICMP e muitas empresas o bloqueiam, dando a falsa impressão de que o servidor está fora do ar. Use nc -zv IP PORTA para testar se o serviço específico (ex: banco de dados na porta 5432) está realmente respondendo, ignorando o bloqueio de ping!
