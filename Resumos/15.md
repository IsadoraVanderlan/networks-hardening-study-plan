# Resumo de Estudos: DNS — Sistema de Nomes de Domínio (Domain Name System)

---

## 1. O que é o DNS?

O **DNS** é um sistema distribuído e hierárquico que atua como a "lista telefônica" da internet. Sua principal função é traduzir nomes de domínio legíveis por humanos (ex: `exemplo.com.br`) em endereços IP numéricos compreendidos pelos roteadores (ex: `192.0.2.1` ou `2001:db8::1`).

- **Camada no Modelo OSI:** Camada de Aplicação (L7).
- **Porta e Protocolos:**
  - **Porta 53 UDP:** Utilizada para a grande maioria das consultas e respostas rápidas.
  - **Porta 53 TCP:** Utilizada quando a resposta excede 512 bytes ou durante a transferência de zonas (_Zone Transfers_) entre servidores DNS.

---

## 2. A Estrutura Hierárquica do DNS

A árvore de nomes do DNS é organizada em níveis hierárquicos:

1. **Root Domain (Domínio Raiz):** Representado por um ponto (`.`) no final do FQDN (_Fully Qualified Domain Name_). Gerenciado por 13 grupos de servidores raiz no mundo.
2. **Top-Level Domain (TLD):** Sufixos de alto nível organizados por tipo (`.com`, `.org`, `.net`) ou código de país (`.br`, `.us`).
3. **Second-Level Domain (SLD):** O nome registrado pela organização ou usuário (ex: `google` em `google.com`).
4. **Subdomínio:** Divisões internas gerenciadas pelo proprietário do domínio (ex: `app.exemplo.com` ou `vpn.exemplo.com`).

---

## 3. Fluxo de Resolução DNS (Recursivo vs. Iterativo)

Quando um usuário digita `https://site.com` no navegador, o processo de resolução segue o seguinte fluxo:

```text
[Cliente/Browser]
       |
  (1)  v  (Consulta Inicial)
[DNS Resolver / Local Cache]  <--->  (2) [Root Server (.)]
       |                      <--->  (3) [TLD Server (.com)]
       |                      <--->  (4) [Authoritative Server (site.com)]
       v  (Resposta Final: IP)
[Cliente conecta via HTTPS]
```

1. **DNS Resolver / Recurser:** O servidor DNS configurado na máquina (ou provedor/cloud) recebe a solicitação. Se a resposta não estiver no cache local, ele inicia a busca.
2. **Root Server:** Indica qual servidor TLD cuida do sufixo `.com`.
3. **TLD Server:** Indica qual Servidor Autoritativo é responsável pelas entradas do domínio `site.com`.
4. **Authoritative Name Server (Servidor Autoritativo):** Detém a zona DNS oficial e retorna o endereço IP final do recurso para o Resolver, que repassa ao cliente e armazena em cache conforme o valor de **TTL** (_Time to Live_).

## 4. Principais Tipos de Registros DNS (_Resource Records_)

| Registro                | Nome Completo         | Função Principal                                                                                                                   |
| :---------------------- | :-------------------- | :--------------------------------------------------------------------------------------------------------------------------------- |
| **A**                   | _Address Record_      | Mapeia um nome de domínio para um endereço **IPv4** (32 bits).                                                                     |
| **AAAA**                | _IPv6 Address Record_ | Mapeia um nome de domínio para um endereço **IPv6** (128 bits).                                                                    |
| **CNAME**               | _Canonical Name_      | Cria um alias/apelido apontando um nome para outro nome de domínio (ex: `www.site.com` $                                           |
| ightarrow$ `site.com`). |
| **MX**                  | _Mail Exchanger_      | Aponta os servidores de e-mail responsáveis pelo recebimento de mensagens do domínio.                                              |
| **TXT**                 | _Text Record_         | Armazena texto arbitrário. Usado extensivamente para validação de segurança (SPF, DKIM, DMARC, validação de certificados SSL/TLS). |
| **NS**                  | _Name Server_         | Especifica os servidores DNS autoritativos responsáveis pela zona.                                                                 |
| **SOA**                 | _Start of Authority_  | Contém informações de controle da zona (servidor primário, e-mail do administrador, número de série e timers de renovação).        |
| **PTR**                 | _Pointer Record_      | Realiza a resolução reversa (mapeia um IP de volta para um FQDN).                                                                  |

## 5. Relevância para Cloud Security e Ameaças

Em ambientes de nuvem (AWS Route 53, Cloudflare, Azure DNS), o DNS é tanto um componente crítico de disponibilidade quanto um vetor de ataque frequente.

### 5.1 Vetores de Ataque Comuns

- **DNS Spoofing / Poisoning:** Injeção de dados falsos no cache de um DNS Resolver para redirecionar usuários para sites maliciosos.
- **DNS Amplification Flood:** Ataque DDoS que explora servidores DNS abertos usando requisições `UDP` com IP forjado (_IP Spoofing_) para direcionar respostas volumosas contra a vítima.
- **DNS Tunneling:** Exfiltração de dados confidenciais através de requisições DNS (dados codificados dentro de subdomínios em consultas `TXT` ou `A`), burlando firewalls que não inspecionam a porta 53.
- **Subdomain Takeover:** Ocorre quando um registro DNS (como `CNAME`) aponta para um recurso de nuvem desalocado (ex: balde S3 deletado). O atacante cria o recurso na nuvem e assume o controle do subdomínio.

### 5.2 Mecanismos de Proteção e Controles em Nuvem

- **DNSSEC (_DNS Security Extensions_):** Adiciona assinaturas digitais aos registros DNS para garantir autenticidade e integridade, prevenindo o _Poisoning_.
- **Route 53 Resolver DNS Firewall (AWS):** Filtra e bloqueia consultas DNS para domínios maliciosos conhecidos (prevenção de C2 e exfiltração).
- **Proteção de E-mail (SPF, DKIM, DMARC):** Registros `TXT` no DNS usados para autenticar a origem de e-mails e combater _Phishing_ e _Spoofing_.
- **Gerenciamento de TTL:** Ajustar o TTL para valores baixos durante migrações em nuvem permite redirecionar o tráfego rapidamente em cenários de _Failover_.

## 6. Resumo Executivo para Entrevistas

> **"O DNS é o protocolo da Camada de Aplicação responsável por traduzir nomes de domínio em endereços IP na porta 53 (UDP para consultas padrão e TCP para respostas grandes ou transferências de zona). Em Cloud Security, além de gerenciar roteamento e failover via TTL, o monitoramento de DNS é vital para prevenir ataques como DNS Tunneling, Subdomain Takeover, envenenamento de cache e amplificação de DDoS."**
